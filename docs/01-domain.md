# 01 — Domain model

Every type below lives in `BrainCore` and is a pure Swift value type. No type in
this document knows about HTTP, SQL, or any model provider.

## Identifiers

**ULID** everywhere. 26 characters, Crockford base32, lexicographically sortable
by creation time, URL-safe. Chosen over UUIDv4 because sort order is free and
because a deterministic total order makes ranking tie-breaks trivial.

IDs are **generated by code, never by a model.** Any ID appearing in model output
that is not in the whitelist the model was given is rejected (`07-harness-spec.md`).

## Time

- Every timestamp is stored UTC, ISO-8601 with explicit offset.
- Every user has one `timezone` (IANA, default `Asia/Kolkata`).
- **"Today" is always computed in the user's timezone, never the server's.**
  Date parsing is relative to that. This is the single most common source of
  off-by-one-day bugs and is tested explicitly.

## Confidence and abstention

**Every classified field is optional and carries a confidence.**

```
Classified<T> {
  value: T?           // nil means "unknown" — always legal
  confidence: Double  // [0, 1]
  tier: Tier          // .t0 | .t1 | .t2 | .t3  — who decided this
  evidence: Span?     // T0/T2 must cite a span of raw text where applicable
}
```

`nil` is never a failure. The eval **rewards abstaining over a wrong guess**
(`04-scorecard.md`). `tier` is recorded so every scorecard can be sliced by it.

## Entities

### Capture
The raw, unprocessed thing the user dumped. Never modified after creation.

| Field | Type | Notes |
|---|---|---|
| `id` | ULID | |
| `rawText` | String | verbatim, never normalised in place |
| `source` | enum | `text`, `voice`, `image`, `share` |
| `createdAt` | Date | UTC |
| `status` | enum | see state machine below |
| `idempotencyKey` | String? | client-supplied; clients retry on bad networks |

**Capture is append-only and is never lost.** If enrichment fails for any reason,
the capture survives in `failed` and is retried. This is a hard invariant tested
under injected failure in B7.

```
raw ──► enriching ──► enriched
          │              │
          └──► failed ◄──┘        failed is always retryable
```

### TaskCategory

What doing the task *involves* — orthogonal to `type`, which says what the
capture *is*. Nine values, taken from the generated datasets where five
selection policies turned out to pivot on it (`docs/13-generated-datasets.md`):

`paperwork` · `errands` · `communication` · `planning` · `deepWork` ·
`chores` · `money` · `learning` · `health`

Assigned at **T0** by a keyword lexicon over the title (`Category.swift`), never
by a model. Measured accuracy and the AI Justification Test entry are in
`DECISIONS.md`; re-measure with `make category-eval`. Abstains rather than
guessing, and a `category` modifier in a `.brain` file overrides it.

### Goal
An outcome that items serve. User-created or confirmed, never silently invented.

`id` · `title` · `status` (`active`, `achieved`, `abandoned`) · `createdAt`

### Edge

| Field | Type | Notes |
|---|---|---|
| `id` | ULID | |
| `from` / `to` | ULID | |
| `kind` | enum | `blocks`, `relates`, `duplicate`, `serves` |
| `confidence` | Double | |
| `source` | enum | `t0Rule`, `t1Model`, `t2Model`, `user` |
| `confirmed` | Bool | **only `user` source may set this true** |

Semantics, stated once so the graph code is unambiguous:

- `A blocks B` — B cannot start until A is done. **Directed, acyclic, enforced.**
- `A relates B` — symmetric, no scoring weight, purely navigational.
- `A duplicate B` — symmetric; resolution merges into the older item.
- `A serves G` — A contributes to goal G. From item to goal only.

**Cycle rule:** any `blocks` edge that would create a cycle is rejected in code,
deterministically, regardless of which tier proposed it. No exceptions, no
confidence threshold that overrides this.

### Correction
The training signal. Written whenever the user changes anything a tier decided.

`id` · `targetId` · `field` · `beforeValue` · `afterValue` · `tier` (who got it
wrong) · `createdAt`

Corrections are the input to T1 personalisation (B6) and to dynamic few-shot
retrieval. They are the most valuable data the product produces.

## Invariants (become property tests in B1)

1. The `blocks` subgraph is always a DAG.
2. A capture is never deleted or lost by any pipeline path.
3. `confirmed == true` implies `source == .user`.
4. Ranking is a strict total order — no two items ever tie (`02-scoring-spec.md`).
5. Scoring is deterministic: same graph in, same ranking out, every time.
6. Every `Classified` field may be `nil`, and `nil` never crashes a downstream stage.
